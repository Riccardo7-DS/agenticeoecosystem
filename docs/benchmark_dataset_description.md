# Benchmark Dataset Description

## Dataset Construction

We constructed a benchmark dataset of **116 tasks** (103 executable, 13 reserved as placeholders for future tools) spanning two complementary task files. The first file covers the Earth Observation (EO) dashboard ecosystem and contains 77 tasks; the second, introduced in this work, contains 39 tasks targeting newly integrated MCP servers for scientific literature retrieval (Arxiv) and geospatial processing (GIS). Together they provide evaluation coverage across five MCP servers: the ESA EO Dashboard narrative and indicator API, the ESA Science Strategy HybridRAG retrieval system, Google Earth Engine (GEE) satellite image download, the Arxiv MCP server, and the GIS MCP server (exposing rasterio, geopandas, shapely, and pyproj tools).

Tasks are organised along four difficulty axes. **Tool Grounding** tasks (37 total: 26 EO + 11 Arxiv/GIS) require a single, correctly parameterised tool call and test whether the agent maps a natural-language instruction to the right function and arguments. **Sequential Reasoning** tasks (18 total: 10 EO + 8 Arxiv/GIS) require a multi-step chain within a single server — for example, searching for a paper, downloading it, and extracting its citation graph. **Cross-agent Synthesis** tasks (26 total: 8 EO + 18 Arxiv/GIS) span two or more servers and test the agent's ability to propagate intermediate outputs across tool boundaries; representative patterns include retrieving a passage from the ESA Science Strategy via HybridRAG and then querying Arxiv for recent publications on that theme, or downloading a multispectral image from GEE, computing an NDVI raster with the GIS tools, and producing a static map visualisation. **Scope Awareness** tasks (22 total: 20 EO + 2 Arxiv/GIS) are control questions that fall entirely outside the system's domain (e.g. restaurant recommendations, cryptocurrency trading); a correct response requires producing *no* tool calls.

Each task consists of a natural-language instruction, one or more reference solutions expressed as ordered lists of `{function_name, arguments}` steps, and structured evaluation fields. Where multiple valid tool orderings or parameter choices exist — for instance, swapping the NIR and Red band indices depending on the channel ordering returned by GEE — both alternatives are provided as separate reference solutions. Automatic scoring is performed by LLM-based judge models (Gemma3-12B, Nemotron-2-12B, and Qwen3-14B), which assign each generated solution a score of 2 (full match), 1 (partial match), or 0 (no match) relative to the reference solutions, yielding per-task accuracy metrics at both the full-match and partial+full-match thresholds.

## Relation to Prior Work

The benchmark is methodologically derived from GeoBenchX, from which it inherits the task data model, the 0/1/2 scoring taxonomy, and the LLM-as-judge evaluation loop. It extends GeoBenchX in several key respects. First, evaluation is performed against a live multi-agent system rather than a single model inference: each task runs through a LangGraph supervisor that routes to dedicated sub-agents backed by real MCP servers, and the generated solution is the actual tool-call trace recorded from execution, not a predicted sequence. Second, the Cross-agent Synthesis category requires the agent to propagate intermediate results across heterogeneous servers within a single query — a scenario not present in GeoBenchX or in general-purpose tool-use benchmarks such as ToolBench (Qin et al., 2023) or API-Bank (Li et al., 2023), which evaluate single-model multi-step calls against mock or sandboxed backends. Third, the benchmark specifically targets the Earth Observation domain and includes a domain-specialized generator (EVE-Instruct, pre-trained on EO scientific literature and ESA domain knowledge) alongside general-purpose models, enabling a controlled test of whether domain specialization yields measurable gains on EO tool orchestration tasks. To our knowledge this is the first benchmark to evaluate LLM agents on real EO MCP tool orchestration, spanning remote sensing data download, raster analysis, coordinate transforms, scientific literature retrieval, and ESA Science Strategy knowledge-graph search.
